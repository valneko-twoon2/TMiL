# テストのルール

## 回帰テスト（必ず守る）

- 不具合を直したら、必ず回帰テストを入れる。手順は `bugfix` スキル
- 先に再現するテストを書いて失敗を確かめてから直す
- `regression` グループに入れ、何が起きていたかを 1 行で書く

## 種類と分類

- テスト名にタグ（`equivalence` `boundary` `regression` `snapshot` `contract` `property` `fuzz`）を入れて分類する。詳しくは docs/testing/02-tags.md
- 新しい関数には、同値分割と境界値の両方のテストを書く（空・0・最大・範囲の端・不正な値）
- 入力の組み合わせが多い純粋関数には、プロパティベースのテストも書く（`property`。フロントは fast-check、バックは proptest）。「落ちない」だけでなく、並べ替えても数が変わらない・行って戻ると元に戻る など、成り立つべき性質を確かめる
- テストを足したり減らしたりしたら `npm run docs:tests` で集計を更新する

## 回し方

- 普段は関係するものだけ: `npm run test:related`
  - 画面を変えた: `-- --e2e-mock`、見た目も変わった: `-- --vrt`
  - バックの挙動を変えた: 必要に応じて `-- --e2e-native`
- 全部は CI に任せる（`npm test` で手元でも回せる）
- カバレッジはフロント・バックとも 80% 以上を保つ

## やらないこと

- テストを通すためだけに期待値を書き換えない。期待値が間違っていたときは、なぜ間違っていたかをコミットメッセージに書く
- 失敗するテストを `skip` で放置しない
- ミューテーションテストは CI では回さない（手動）
