# 本家のタスク マネージャーとの対応

Windows 11 のタスク マネージャーにある機能を、どう作ったかと、違うところです。

## ページ

| ページ         | 作り方                                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------ |
| プロセス       | 種類（アプリ・バックグラウンド・Windows プロセス）に分ける。列は見出しの右クリックで選ぶ         |
| パフォーマンス | CPU（論理プロセッサごとのグラフも）・メモリ（構成の帯）・ディスク・GPU・ネットワーク（アドレス） |
| アプリの履歴   | アプリごとの CPU 時間と読み書きの量。この画面が動いている間だけ記録する（下を参照）              |
| ユーザー       | ユーザーごとにプロセスをまとめ、選んだユーザーのプロセスを下に出す                               |
| 詳細           | CPU 時間・コミット サイズ・ハンドル・スレッド・セッション ID・I/O・GPU・説明の列を足した         |
| サービス       | 開始・停止・再起動。Windows は管理者の確認（UAC）が出る。Linux は systemd（polkit が確認を出す） |

どのページの見出しにも「新しいタスクを実行する」があります（Ctrl+N）。F5 で今すぐ更新、Ctrl+F・Ctrl+E で検索に移ります。

## 種類の分け方（プロセス タブ）

| 種類              | 決め方                                                                           |
| ----------------- | -------------------------------------------------------------------------------- |
| アプリ            | ウィンドウを出しているプロセスを含む（Windows は PowerShell、Linux は `wmctrl`） |
| Windows プロセス  | 実行ファイルが Windows フォルダーにあるか、分からないもの                        |
| システム プロセス | Linux で root のものか、実行ファイルが分からないもの                             |
| バックグラウンド  | それ以外                                                                         |

Linux で `wmctrl` が無いと、アプリを見分けられません（バックグラウンドに入ります）。ウィンドウの一覧は 5 秒ごとに読み直します。

## アプリの履歴

OS の記録（Windows の SRUM）は読めないので、計測結果の累計値（CPU 時間・読み書きのバイト数）の増え方を足し合わせます。

- プロセスは PID と起動時刻で見分け、初めて見たときの値から数える（それより前の分は数えない）
- 画面が隠れている間は計測しないので、その間に始まって終わったプロセスは数えない
- 記録は localStorage に、10 回の計測ごとと、隠れたときに保存する
- Windows の読み書きの量は、ディスク以外（ネットワークなど）の入出力も含む

## 効率モード・中断

| 操作       | Windows                                         | Linux                    |
| ---------- | ----------------------------------------------- | ------------------------ |
| 効率モード | `SetProcessInformation`（EcoQoS）と優先度「低」 | nice 19 と `chrt --idle` |
| 中断・再開 | `NtSuspendProcess`・`NtResumeProcess`           | SIGSTOP・SIGCONT         |

OS からは「効率モードか」を読めないので、この画面で入れたものだけを覚えて状態に出します。Linux で効率モードを外す（優先度を上げ直す）には管理者権限が要ります。

## 使用状況のグラフ・メモリ増加中（本家に無い機能）

プロセスの右クリックメニューの「使用状況のグラフ」で、そのプロセスの CPU とメモリの推移を開きます。計測のたびに画面側でプロセスごとに直近 300 回分（1 秒ごとなら 5 分）を覚えます。PID と起動時刻で見分けるので、PID が使い回されても混ざりません。

メモリが増え続けているプロセスは、プロセス タブの状態に「メモリ増加中」と出し、グラフにも注意を出します。判断は `lib/process/usage.ts` の `memoryGrowth` で、次の全部を満たすときです。

- 計測が 60 回以上ある
- 推移を 4 つに分けた平均が、毎回増えている（一度だけ跳ね上がってそのまま、は含めない）
- はじめより 50 MB 以上、かつはじめの 2 割以上増えている

## 作っていないもの

| 機能                             | 理由                                                                        |
| -------------------------------- | --------------------------------------------------------------------------- |
| プロセスごとのネットワーク使用量 | OS の仕組み（ETW など）が要り、管理者権限なしでは取れない（接続の数は出す） |
| ダンプ ファイルの作成            | 資格情報を盗む手口と同じ動きで、セキュリティ ソフトに止められる             |
| 待機チェーンの分析・UAC の仮想化 | Win32 API を細かく呼ぶ必要があり、手間に対して使う場面が少ない              |
| ユーザーの切断・サインアウト     | 手元で確かめようがなく、誤操作の影響が大きい                                |
| スタートアップへの影響           | 起動にかかった時間の計測が要る                                              |
| 電力消費の列                     | OS の推定値を読めない                                                       |
